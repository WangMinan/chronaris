# 鼎新简化下游评价协议 v1

冻结日期：2026-07-16
代码基线：`719c47c58bcea9149bb7d16b33e2980d6d1cda25`
执行分支：`codex/simple-downstream-rebuild-20260715`

## 1. 研究目标

本协议只回答一个问题：在相同鼎新人机双流、相同时间边界和相同轻量下游算法下，朴素时间同步、MulT 适配实现、ContiFormer 适配实现和 Chronaris 输出的融合表示，哪一种更适合未来机动预测与未来生理状态预测。

本轮回退的是研究协议和默认执行入口，不回滚代码历史，不删除既有数据冻结、工程修复、仿真、消融或历史实验产物。`0a38171a8310b5f9888d978cf4b7d89b89ca9a98` 只作为历史快照，不作为新开发基线。

## 2. 数据和统计单位

- 数据固定为 2 个架次、3 个视图和 111 个 5 秒基础窗口，不依赖新增鼎新数据或人工标签。
- 每个任务样本读取目标时刻前 30 秒，预测随后 5 秒；输入区间为 `[t-30s, t)`，目标区间为 `[t, t+5s)`。
- 现有原始点审计给出 93 个候选上下文，其中每个视图最后一个候选的未来数据不足 5 秒，因此正式任务应有 90 个完整 view-context。
- 生理状态预测以 90 个 view-context 为统计单位。
- 机动目标在同一架次、同一目标时刻的多个视图间重复。任务清单必须生成 `vehicle_context_id = sortie_id + target_start_offset_ms`，预期得到 60 个唯一 vehicle-context；实际数量由任务审计确认并写入产物。

若完整目标数量、唯一上下文数量或时间边界与上述合同不一致，程序必须失败并报告数据问题，不得静默删样本。

## 3. 正式任务

### 3.1 未来机动强度连续预测

机器任务 ID：`dingxin_future_maneuver_score_v1`。

目标为未来 5 秒内由载机三轴加速度、俯仰、横滚等已确认运动学语义构造的连续机动强度。字段有效性、中心尺度和聚合参数只在当前外层训练折拟合，留出架次只应用训练参数。

主指标为：

- 斯皮尔曼秩相关系数；
- 以训练折目标四分位距归一化的平均绝对误差；
- 相对“当前最后 5 秒机动状态延续”基线的均方误差技能。

技能定义为：

```text
skill_vs_current_maneuver = 1 - model_squared_error / persistence_squared_error
```

正值表示优于当前状态延续，零表示相当，负值表示不如延续基线。

### 3.2 未来机动强度分类

机器任务 ID：`dingxin_future_maneuver_class_v1`。

低、中、高三类只由当前外层训练折中的未来机动连续分数三分位数生成，留出架次只应用训练阈值。该任务用于直接回应机动动作分类需求，是连续预测的辅助任务，不取代连续分数主结果。

指标为宏平均 F1、平衡准确率和混淆矩阵。若留出折缺少某类，仍使用冻结的三类标签集合，并在报告中展示真实支持数。

### 3.3 未来生理字段预测

机器任务 ID：`dingxin_future_physiology_fields_v1`。

目标为未来 5 秒内 12 个已确认 EEG/SpO2 生理字段各自的中位数，不再把字段压缩成含义不清的单一指数，也不再构造高剩余响应分类。

- 字段有效性、中位数和四分位距只在当前外层训练折拟合。
- 下游算法使用同一个多输出 Ridge 回归器预测全部有效字段。
- 持久性基线使用输入上下文最后 5 秒内各字段的中位数。
- 主指标为相对持久性技能、字段级标准化 RMSE 宏平均和字段级标准化 MAE 宏平均。
- 补充报告 EEG 字段组、SpO2 字段组以及取得正技能的字段比例。

持久性技能定义为：

```text
skill_vs_persistence = 1 - model_squared_error / persistence_squared_error
```

分母为零的字段结构化标记为不可计算，不得用常数或极小数伪造有限结果。

## 4. 输入边界

正式输入允许：

- 目标开始前 30 秒内的生理观测和航电观测；
- 历史速度、加速度、俯仰、横滚和过载等运动学信息；
- 相对于当前上下文起点的时间戳、采样间隔和缺失掩码；
- 物理字段语义。

正式输入禁止：

- 未来 5 秒目标窗口中的任何观测；
- 由未来目标确定性生成的统计量；
- 绝对飞行进程、基础窗口编号、样本 ID、视图 ID、飞行员 ID、架次 ID 和折 ID；
- 使用全数据或留出架次拟合的标准化、主成分分析、阈值或字段选择参数。

身份字段允许保存在清单中用于分组、审计和结果聚合，但不得进入模型张量。

过去窗口中的运动学字段是合法预测信息。历史管线删除的 20 个机动标签源字段不再自动从新主协议的过去输入中删除；“删除历史运动学字段”只允许作为附录敏感性检查。

## 5. 方法与统一表示

正式比较包含：

1. 生理单流；
2. 航电单流；
3. 朴素时间同步；
4. MulT 适配实现；
5. ContiFormer 适配实现；
6. Chronaris。

论文和报告必须写明 MulT、ContiFormer 为当前仓库面向因果输入合同的适配实现，不写成官方仓库逐行复现。

主评价使用任务无关的冻结统一表示：

- 相同样本和 30 秒输入；
- 相同 96 点因果查询网格；
- 每个样本形成 64 维窗口表示；
- 相同无标签池化规则；
- 编码器训练不得读取三个新任务的目标；
- 三个任务复用同一份表示，不为某个任务单独重训编码器。

不再重跑端到端联合训练。既有端到端结果只用于说明小样本任务微调的过拟合风险，不进入新主表。

## 6. 表示兼容性审计

现有 checkpoint 和 270 份表示不能默认复用。正式实现必须输出 `representation_compatibility_report.json`，逐项检查：

- 90 个新上下文是否能与表示逐项匹配；
- 表示是否只读取目标开始前的数据；
- 编码器训练是否未读取新任务标签；
- 历史运动学字段政策是否符合本协议；
- 模型配置是否与论文最终配置一致；
- 六种方法是否使用相同的无标签池化合同。

总判定只能取：

```text
reusable_as_primary
reusable_as_sensitivity_only
retraining_required
```

上下文、时间边界、任务标签隔离或字段合同任一项不满足，均不得判为 `reusable_as_primary`。代码基础设施可以复用，重型产物必须服从新协议。

## 7. 划分和重复计权

### 7.1 主要评价

留一架次是主要评价，共两个折。它只写成“现有两个架次上的协议冻结后分组确认评价”，不写成从未接触的盲测或外部泛化证明。

- 两个折分别报告，不只报告平均值。
- 可以报告两个折拼接后的折外总体指标。
- 架次数量不足以支持显著性检验，不报告窗口级显著性结论。

### 7.2 诊断评价

留一视图只用于回答更换飞行员生理流后，同一飞行过程的表示是否稳定。它不作为新飞行条件泛化证据，也不决定主结论。

### 7.3 机动任务聚合

- 训练时，同一 `vehicle_context_id` 的样本权重之和固定为 1；若有两个视图，每个权重为 0.5。
- 评价时，先对同一 `vehicle_context_id` 的连续预测或分类概率求平均，再以唯一 vehicle-context 计算指标。
- view 级机动结果只作为诊断，不进入主指标。

生理任务按 view-context 训练和评价，不进行上述去重。

## 8. 下游算法和冻结配置

所有方法共享相同消费者：

- 未来机动连续预测：`StandardScaler` 加 `Ridge(alpha=1.0)`；
- 未来机动分类：`StandardScaler` 加 `LogisticRegression(C=1.0, class_weight="balanced", max_iter=5000)`；
- 未来生理字段预测：`StandardScaler` 加多输出 `Ridge(alpha=1.0)`。

标准化只在当前外层训练折拟合。消费者不读取绝对时间和身份字段。正式随机种子固定为 `17/29/43`；随机种子用于表示训练、消费者可复现配置和报告分组。

本协议采用固定消费者参数，不再建立候选网格或根据外层结果调参。正式留一架次结果打开后，只允许修复能够由测试复现的程序错误，不允许改变目标、字段、模型、池化、消费者或划分。

### 8.1 编码器配置和训练预算

五个可训练编码器沿用任务目标打开前已经完成的无标签候选筛选结论：

- 生理单流：候选 A；
- 航电单流：候选 C；
- MulT 适配实现：候选 A；
- ContiFormer 适配实现：候选 A；
- Chronaris：候选 A。

两个留一架次折和三个随机种子统一使用最多 50 epoch、batch size 32、patience 8。早停只读取当前外层训练架次内部的公共自监督 validation 损失；三个新任务的目标、留出架次观测和留出架次指标均不得参与编码器训练或早停。训练结束后，同一冻结编码器为当前外层训练清单和留出架次清单导出完整表示；旧内部划分中因上下文重叠而未参与无标签拟合的边界样本仍可作为冻结下游算法的训练样本，不得再次从 90 个任务上下文中删除。

正式训练采用单 CUDA 进程串行执行，生理单流、航电单流、MulT、ContiFormer 和 Chronaris 均优先使用同一 RTX 4090。只有可复现的设备故障才允许按 checkpoint 设备历史原地恢复到 CPU，且必须写入运行清单。

2026-07-16 的工程冒烟只使用 3 epoch、batch size 8、patience 3，用于验证恢复、字段合同和运行资源；其分数与最佳 epoch 不参与上述正式预算或配置选择。

## 9. 执行顺序与门限

1. 固化协议和分支，不运行新指标。
2. 生成新任务清单并验证 90 个完整 view-context、60 个唯一 vehicle-context 和严格未来隔离。
3. 生成表示兼容性报告；若结论不是主结果可复用，则按新字段合同重训或重导表示。
4. 用一个留一架次折、seed 17 完成工程冒烟，只检查数据、表示、消费者、持久性指标、聚合和恢复。
5. 冒烟通过后，使用冻结配置完成两个留一架次折、三个随机种子和六种方法的一次正式确认。
6. 以较低预算运行留一视图诊断。
7. 复用既有仿真、时间机制和消融证据，重新制图但不重训，并同时呈现 Chronaris 有利与不利结果。

冒烟通过条件只判断程序和合同正确性，不以模型分数放行或阻断研究。正式确认完成后停止新增任务和结果驱动调参。

## 10. 既有证据复用边界

既有 35 个仿真压力场景、三随机种子、时间机制评价和四项 Chronaris 消融不重训。论文整理固定覆盖时钟偏移、缺失、采样抖动、噪声和混合压力，不能只保留有利场景。

只有在 Chronaris 架构、连续时间处理、物理约束和因果掩码配置与最终模型一致时，既有消融才可作为最终配置的直接证据；否则必须标记为前期机制证据。
