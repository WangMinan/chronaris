# 固定数据证据策略

日期：2026-07-10  
状态：当前下游评估与论文实验主线的强制决策

## 1. 决策目的

本策略回答三个问题：后续实验还能使用什么数据、不同数据承担什么证据角色、什么结果可以进入论文主结论。

后续代码、实验、图表和论文材料若与本策略冲突，以本策略为准；需要改变时必须新增决策记录，不能在训练脚本参数中静默改变。

## 2. 已锁定的事实

| 事项 | 锁定结论 |
| --- | --- |
| 新增鼎新一手双流数据 | 不可作为执行依赖 |
| 新增飞行员人工评价、专家事件标注或 NASA-TLX | 不可作为执行依赖 |
| 可用鼎新数据 | 当前两个架次、三个双流视图、111 个 5 秒窗口 |
| 可用上游服务 | 当前本机 MySQL 与 InfluxDB 中已存在的数据；只允许读取现有两个架次 |
| 公开数据 | 沿用 UAB/NASA 公开数据适配与校准证据 |
| 脚本生成数据 | 允许，但只作为仿真真值、机制验证和压力测试 |
| LLM | 只用于字段语义归一、规则复核、运行解释、场景说明和人工复核材料组织 |

“不再获得新数据”不等于放弃现有数据库副本。第一轮执行应把当前两个架次的可复现实验输入冻结到本机忽略目录；冻结动作不得扩大架次、视图或飞行员范围。

## 3. 四层证据及职责

### 3.1 鼎新现有真实双流

承担：

- 证明真实人机双流读取、连续对齐、融合表示导出和下游消费链路可运行。
- 运行机动强度弱监督分类和机动诱发生理响应预测。
- 比较生理单流、航电单流、朴素同步、MulT、ContiFormer 和 Chronaris。
- 检查跨视图方向一致性、数据泄漏和模型失效情况。

不承担：

- 人工工作负荷真值验证。
- 专家机动科目识别。
- 基于三个视图作强统计显著性推断。

### 3.2 模型无关半物理仿真双流

承担：

- 提供已知统一时间轴、时钟偏移、漂移、机动边界、负荷状态和生理响应时延。
- 验证连续时间对齐、物理一致性约束、因果滞后和缺失鲁棒性。
- 支撑仿真负荷提前评估、机动状态分段和跨生成族泛化。

强制边界：

- 生成器只生成原始双流和独立真值，不生成任何方法的融合向量。
- 生成器 API 不接受方法名称、模型配置、checkpoint 或候选编号。
- 训练生成族与锁定测试生成族不同，防止模型与生成方程同构。
- 仿真结果不得与鼎新指标求平均或合并成一个排行榜。

### 3.3 UAB/NASA 公开数据

承担：

- 提供人体状态任务上的外部适配、校准和上下文构造第二输入流参照。
- 检查代码在公开数据上的可迁移性。

不承担：

- 等价替代鼎新真实航电流。
- 参与六方法鼎新主表或仿真主表的平均排名。
- 为鼎新弱监督标签提供人工真值背书。

### 3.4 融合表示结构诊断

ClaSP、Matrix Profile、motif、discord 和片段复盘保留为附录诊断，只回答“表示中是否能发现结构片段”，不替代应用下游任务，不参与模型选择。

## 4. 现有 E3 分支处理决策

`implement/fusion-stream-structure-20260707` 保留为历史实验分支，不整体合并。

允许选择性复用：

- OOF 表示与 checkpoint manifest 的校验思路。
- 进度、resume、fold status 和 evidence manifest 的写出方式。
- ClaSP/STUMPY evaluator wrapper、结构化 unavailable 状态和相关单元测试。
- 通用表示长表读取与禁止 sidecar 列的检查。

禁止继承：

- 直接提交旧分支的大量 checkpoint、逐窗口图件和大型 evidence manifest。
- 把回归任务训练后的 pooled embedding 当作通用融合流的默认做法。
- 480、128、64、9710 等不同维度直接进入公平下游比较。
- 候选必须改善 E3 才能入选的筛选规则。
- 根据方法名称改变相位、异常幅值或噪声的 synthetic fixture。

## 5. 数据冻结与存储边界

### 5.1 本机重型输入

原始点、准备后的 dense bundle、checkpoint、逐样本预测和完整训练日志写入：

```text
artifacts/application_evaluation/<run_id>/
```

该目录已被仓库顶层 `.gitignore` 覆盖，不允许通过 `git add -f` 入仓。

### 5.2 可提交的紧凑证据

每轮只在 `docs/artifacts/runs/YYYY-MM-DD_intent/` 保留：

- 数据、划分、表示和训练 manifest。
- fold 指标、汇总指标、运行状态和 resume command。
- 论文使用的紧凑图表。
- claim boundary 与 evidence manifest。

manifest 可以记录相对本机重型目录的路径和 SHA-256，但不得包含数据库密码、token、连接串或原始高频值。

### 5.3 读取失败行为

若当前数据库副本无法再次导出原始异步点：

1. 不创建伪原始数据。
2. 使用现有 `2026-05-02_feature-export-*-allwindow-clean` 表示完成“对齐后鼎新证据”。
3. 将需要原始异步点的六方法公平对比标记为 `raw_snapshot_unavailable`。
4. 仿真主线继续执行，但不得宣称它补齐了鼎新真实实验。

## 6. 论文可写结论的晋级条件

### 6.1 真实弱监督任务

只有同时满足以下条件，结果才可进入真实数据主表：

- 外层测试组没有参与标签阈值、标准化、字段筛选、PCA 或超参数选择。
- 六方法消费完全相同的样本 ID、输入字段集合和外层划分。
- 标签源字段排除审计通过。
- 生理单流和航电单流均被报告。
- 每个 view fold 的原始值可追溯。

### 6.2 仿真任务

只有同时满足以下条件，结果才可进入仿真主表：

- 生成器方法无关测试通过。
- 训练与测试生成族隔离。
- 同一潜在轨迹的 clean/stress 观测成对生成。
- oracle 标签、时钟真值和响应时延均可从 manifest 重建。
- 统计单位为仿真架次或 pilot profile，而不是窗口。

### 6.3 Chronaris 优势表述

不要求 Chronaris 在所有指标上全面第一。正文主论断至少需要：

- 在鼎新生理响应任务或仿真负荷任务中优于最佳深度融合基线，且有正向双流增益；以及
- 在时间偏移、漂移、缺失或响应时延增强时，性能下降慢于最佳基线；以及
- 对应消融能解释连续时间、物理约束或因果滞后的贡献。

若只在干净同步条件下领先，不足以证明连续时间优势；若只优于单流但不优于 MulT/ContiFormer，只能证明融合有用，不能证明 Chronaris 最优。

## 7. 明确禁止的表述

- “完成真实飞行员工作负荷人工评估”。
- “得到专家评价或专家事件边界验证”。
- “仿真数据等价于新增现场数据”。
- “公开数据第二输入流等价于真实航电流”。
- “LLM 生成标签替代专家真值”。
- “Chronaris 在所有任务和条件下全面优于所有基线”，除非锁定结果确实逐项支持。

## 8. 变更控制

下列变化必须先更新本策略和任务规格，再运行实验：

- 增减数据来源、架次或 pilot profile。
- 修改主任务标签公式、上下文长度或预测时域。
- 修改主方法集合、外层划分或主指标。
- 让某个方法获得其他方法没有的数据增强或预训练数据。
- 把附录诊断升级为模型选择条件。
