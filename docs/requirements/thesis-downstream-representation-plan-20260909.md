# 融合表示下游评价与近期模型接入方案

讨论日期：2026-09-09；同步日期：2026-09-10。本文依据用户在本次会话中确认的评价方式，作为下一阶段的研究与开发入口。文档同步已完成；9 月 10 日[阶段 1](../artifacts/runs/2026-09-10_v4-stage1-repair/report.md)完成导出池化、失败终态修复与已有计算复用核验。阶段 2 已完成[共同下游合同与真实开发验收](../artifacts/runs/2026-09-10_v4-stage2-contract/report.md)，后续开展近期方法接入和必要的表示汇总、下游重建。

## 1. 已确认的研究目标

本轮检验不同融合方法输出的特征对下游任务是否有帮助。相同原始样本分别经过 Chronaris 连续融合模型、MulT 多模态变换器、ContiFormer 连续时间变换器及近期对照方法，再分别训练相同类型的下游算法，在相同评价样本和任务标签上比较。

主流程为：**相同观测与划分 → 各方法提取融合表示 → 冻结表示模型 → 各自训练相同类型的下游算法 → 比较任务效果与运行成本。** “相同算法”指相同模型结构、训练规则和调参机会，每种表示分别拟合下游权重，不共用一组已经训练的分类器或回归器。

用户确认当前采用可重新训练下游算法的方式。潜在特征是编码器提取的数值表示，不要求每个维度都对应一个生理字段；本轮不以接入另一组既有固定评估程序为执行前提。真实鼎新压力、精神状态和具体机动动作的业务任务及独立标签目前不可获得，现有可复现任务用于组件验证，后续真实业务验收作为证据增强方向。

既有生理字段预测继续检查表示中的生理变化信息。新增完整未来序列预测矩阵不作为本轮主线；近期模型的原生预测或分类成绩只可作另列的补充，不能替代融合表示的共同下游评价。已有仿真、机制和压力结果继续承担对应的受控验证作用。

| 数据与任务 | 标签或目标来源 | 结果可以说明什么 |
| --- | --- | --- |
| 鼎新未来生理字段回归 | 历史输入之后 5 秒的有效生理字段中位数 | 表示对未来生理观测的预测信息；不称为压力或精神状态识别 |
| 鼎新机动强度分类与回归 | 训练角色拟合的运动学强度分数及低、中、高阈值 | 运动强度相关信息；不称为具体机动动作类别识别 |
| CogPilot 虚拟飞行难度分类 | 公开数据已有难度标签 | 航空相关任务的下游可用性，不等同于压力真值 |
| CogPilot 离线事件条件响应 | 事件后 8 秒与事件前 2 秒的皮肤电导中位数差 | 事件条件下的生理响应估计，不称为在线事件提前预报 |
| CLARE 认知负荷分类与回归 | 原始 10 秒标签区间评分；分类阈值 7 | 公开多生理模态上的负荷任务表现，不直接外推为鼎新业务效果 |
| 仿真负荷、机动分段、时间机制和压力评价 | 已知生成过程与固定扰动 | 受控条件下的任务、机制与鲁棒性证据 |

鼎新按去重后的单记录时间块评价执行，保留两个生理视图。编码器训练、验证和留出分别为 12/3/3 个航电时段，边界隔离 12 个时段；冻结编码器后的下游拟合使用留出前 21 个合法时段，同一航电时段的视图权重之和为 1。当前 11 个生理字段有效，具体清单和角色以[去重验收](../artifacts/runs/2026-09-08_v4-dingxin-deduplicated/report.md)及代码加载结果为准。旧的两个命名架次不再作为独立架次重复计入。

公开数据沿用已准备的固定开发受试者、三折开发划分与五折确认池；本轮接入验证只使用开发角色。统计以受试者为单位；仿真以参数档案为单位；鼎新逐种子描述单记录结果。窗口、视图、折和随机种子不能虚增独立样本量。继续保留原始观测和已有不利结果，不依赖新增鼎新数据、专家标签或生成标签作为真实业务真值。

## 3. 下游算法与公平比较

先复用现有下游实现。鼎新使用固定参数的逻辑回归和逐字段岭回归，保留状态延续及生理持久性参照；公开数据使用线性算法为主，MiniROCKET 时序卷积特征方法为补充。原仿真中的因果时序卷积和持续时间解码继续属于仿真证据，不因文档同步而扩大鼎新算法范围。

同一任务下，各方法共享样本、输入可见时段、目标、划分、指标和下游训练规则。归一化、降维、字段筛选和目标阈值仅在对应训练角色拟合；调参使用原有内部验证角色。分类报告宏平均 F1，回归报告均方根误差及既有字段级、持久性指标，保留样本覆盖、无观测和长尾结果，不按成绩删窗口。

自监督与任务引导路线分别成表。任务引导路线从合法初始化适配编码器，再移除训练任务头、冻结和导出，重新拟合下游算法。记录每种方法的外部预训练来源、目标域标签使用、冻结层和可训练参数；监督信息不同的设置不得混写为同监督比较。若论证跨任务复用，需要预先指定未直接参与编码器任务监督的已有验证任务，并在完整实验前冻结该分配。

现有实现提供每窗口 64 维汇总特征和 96 点序列表示。近期方法先核验实际中间表示，不能把最终预测值包装成融合特征，也不能把一个窗口向量复制 96 次冒充时序结构。维度投影须仅在训练角色拟合，记录输出语义、容量和成本。阶段 3 已核验近期方法的实际末端隐藏表示、维数及共同线性下游，详见[接入合同](recent-model-adapters-v1.md)；不将其声明为逐时刻序列能力。

逐时刻表示遵守对应时刻的历史可见域；窗口末端表示只允许读取该窗口截止前的观测。两类时间合同分别标记，不用窗口末端的完整历史表示证明逐时刻在线能力。输入重采样、缺失处理和语言提示均记录来源；提示不得含目标派生答案、身份或未来信息。

## 4. 近期方法接入范围

TimeCMA 语言模型增强时序方法与 Chronos-2 预训练时序模型是必做接入与实跑验证项；SensorLLM 传感器—语言对齐模型尽量纳入。下表列出已有官方来源与需要验证的能力，本表保留接入范围，已完成的工程实跑见[阶段 3 报告](../artifacts/runs/2026-09-11_v4-stage3-models/report.md)，完整研究比较仍待后续执行。

| 方法 | 本轮工作 | 必须说明的差异 |
| --- | --- | --- |
| [TimeCMA](https://github.com/ChenxiLiu-HNU/TimeCMA) | 固定官方版本，接入语言表示生成与缓存、模型执行、中间表示提取及共同下游评价 | 原生逐点未来序列监督与现有汇总目标不同；不得仅靠统一最后指标就称为同监督比较 |
| [Chronos-2](https://github.com/amazon-science/chronos-forecasting) | 固定模型权重和版本，检查合法历史输入、实际表示接口与下游适配，区分冻结使用和适配 | 属于时序基础模型；零样本原生预测与经过标签适配的表示评价分别记录 |
| [SensorLLM](https://github.com/cruiseresearchgroup/SensorLLM) | 核验通道语义、数据加载、文本模板、传感器—语言对齐与分类阶段，开展显存和短训检查 | 需要领域适配，难度尚未实测；不能只更换分类头便认定适配完成 |

接入先完成版本与权重登记、单批推理、表示导出，再用真实开发样本完成下游拟合与预测。若某个必做方法无法合理提供共同下游所需表示，须报告具体接口、监督或资源原因，与用户讨论调整；不静默淘汰，也不以另一个原生预测任务替代主交付。SensorLLM 的可行或不可行结论同样需要实测依据。

大语言模型（LLM）用于字段语义归一、规则复核和运行解释的辅助模块继续保留。它与 LLM 参与表征的研究对照分别记账，辅助生成材料不替代真实任务标签。

## 6. 环境、实验规模与成本

继续使用实验室现有 RTX 4090 和 `/home/wangminan/env/anaconda3/envs/chronaris/bin/python`。正式神经网络训练使用 CUDA（统一计算设备架构）；启动前检查设备、空闲资源、输出盘空间及现有任务锁。CPU 承担预处理、适合的下游拟合和汇总，不静默回退为 CPU 长训。

输入缓存与已有产物保留原位，当前失败运行根为 `/mnt/e/chronaris-v4-results/2026-09-08-v4-complete`，对应冻结工作树为 `/home/wangminan/projects/chronaris-runtime-v4-code-complete-20260908`。新代码不直接改写冻结工作树。依赖安装先检查现有环境兼容性；权重、大缓存和逐样本输出放在被忽略目录，只提交配置、代码和紧凑证据。

成本表至少包含总参数、可训练参数、适配耗时、峰值显存、表示导出延迟与吞吐。带语言缓存的方法分别报告首次生成及重复使用成本。任务质量、鲁棒性和成本分别展示，不以模型规模或最终排名推定另一项优势。
