# 论文主线连续对齐与语义融合评价协议 v3.1

日期：2026-09-01。适用分支：`research/thesis-continuous-semantic-fusion-202609`。

本协议是 [评价协议 v3](thesis-continuous-semantic-fusion-evaluation-v3.md) 的首个训练内 minor 版本。v3 的数据边界、四个唯一候选、损失权重、随机种子、外层隔离、硬门、最多两轮改进和停止条件全部保持不变。本版本只修正高频原生时序的等价执行、运行存活记录和五分类时移门禁测量；不得据此读取或修改外层协议。

## 1. 触发原因与历史处理

首次四候选长跑启动后，checkpoint 协议哈希会在单元开始时读取源码，而运行期间又完成了墙钟心跳修复，导致不同单元不再绑定同一源码快照。该批仿真 12 单元和鼎新首折 6 单元只保留为工程诊断，统一标记 `superseded_due_to_source_protocol_drift`，不参与候选排序、机制门或论文表格。

v3.1 从新的产物根完整重跑。状态文件同时冻结 Git commit、候选训练源码 SHA-256、runner SHA-256 和协议版本；任一项变化时 resume 必须直接失败。checkpoint v2 新增固定的候选训练源码 SHA-256，兼容检查不允许跨源码续训。

## 2. 数值等价的高频执行修复

- ODE-RNN 的 GRU 观测更新由逐样本调用改为同一时间点的批量调用，mask 后的状态更新规则不变。
- 观测重构和投影由逐时间点调用改为对完整隐藏状态张量的一次批量调用，网络、mask、输出形状和梯度路径不变。
- 不删除、插值、合并或降采样原生观测；单步 Euler、96 个查询点、64 维表示和全部损失保持不变。
- 输出与梯度分别同旧逐样本、逐时间点实现对照，容差固定为输出 `rtol=1e-6, atol=1e-7`，梯度 `rtol=1e-5, atol=1e-6`。

CogPilot 四受试者真实原生窗口的一轮 CUDA 对照由 `1438.6` 秒降至 `573.2` 秒；训练 batch 从 4 增至 13 后为 `190.4` 秒，峰值显存 `3392.5 MiB`。后两者合计约 `7.56` 倍加速，且未改变输入或模型数学合同。

## 3. 训练内预算与门禁测量

- 仿真与鼎新维持 batch size 4；公开高频数据使用 batch size 16。所有候选在同一数据内共享 batch、epoch 和分组规则。
- CogPilot 训练内筛选固定前 5 名受试者，每个“受试者×难度”保留首个样本；只使用首个外层训练集中的分组 validation，不评价外层样本。
- CLARE 固定前 8 名受试者，每个“受试者×实验”在不读取标签的前提下选择时间中点附近首个双流有效窗口；五个 outer-train 各自建立分组 validation。29 个选定窗口的低/高负荷分布为 16/13，15 个训练划分均覆盖两类。
- 显式时移训练目标不变。仿真机制门额外对每个 validation 样本完整评估 `{-10,-5,0,+5,+10}` 五种时移并报告均衡准确率，避免 11 个样本只抽一个时移造成的高方差；该诊断不进入 early stopping。
- 单个 CUDA 进程运行；独立墙钟线程每 30 秒输出存活心跳。CUDA 失败时保留每 epoch 原子 checkpoint 并直接失败，不转 CPU。

## 4. 重跑与收口

v3.1 必须在同一冻结 commit 下连续完成仿真、鼎新、CogPilot 和 CLARE 的四候选、三随机种子训练内筛选。只有全部训练内结果完成后才运行门禁和排序；若仍有机制门失败，剩余最多一次单原因改进机会。外层结果仍保持关闭。
