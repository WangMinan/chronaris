# 一次性代码交付复核

本轮先收口候选比较、公开三折三种子及自动选型代码，再交由固定入口持续执行。用户要求先交付代码；工程测试不代替研究实验完成。

## 复核范围与计划

复核初筛、压力、公开首折、完整复核、采用、冻结和正式主表的真实调用链；检查每个等待分支是否有对应执行代码、是否绑定同一数据角色、是否保留失败与恢复位置。复杂度复核使用 Ponytail Review（冗余设计检查），正确性另行检查。

## 发现与实现

- 原两段接续脚本硬编码历史目录、来源哈希及后台进程，不能作为独立复现入口。统一入口改为显式运行目录，阶段调用复用现有训练器和消费者。
- 公共增强和多时域预测可能被融合模型采用，但基线没有完整比较入口。新初筛清单补齐四种基线的两项公共候选，公开入选时给予相同首折机会；被共同规则淘汰的候选无需强行进入三种子复核。
- 预定的两种子长缺失状态增长会导致冻结永久等待。新增一次有界的解析衰减复核，激活依据绑定开发文件；复用旧复核的完整结果目录，新增候选依次完成仿真和公开三折三种子及压力评价。收益不达标仍保留原参考与负面结论，不无限搜索。
- 核心消融的自定义确认目录没有传给实际评价子进程，已贯通调用参数，避免生成在新目录、读取旧目录。
- 总入口只自动重试显卡锁等待。执行错误留下独立日志与状态并停止；同源码瞬时故障的重试必须显式指定，不把执行失败直接算作候选淘汰。

## 交付边界

当前工作交付选型、正式主表、压力、核心消融、独立时间机制、分组统计及中文图表的运行代码。实际正式神经检查点在确认前再次检查历史隔离；报告以完成收据和原始预测为依据，不把工程检查写成研究成绩。历史 18 个初筛配置及检查点保持原样，新源码不静默续训旧检查点。
