# v4 冗余、正确性与并行性能复核

本次改动把重复取批和 CPU 消费者拟合收敛到共享实现，同时减少验证前向，并补齐 CPU 与 GPU 重叠执行所需的部分恢复合同。[冗余清单](ponytail-review.md)按用户指定的 ponytail-review 技能整理；正确性和性能作为额外复核，代码修复由用户本轮直接授权。

## 已验证的改动

公共损失与机制验证复用同一组正、负输入前向。在包含显式时移目标的测试中，两个批次的编码器调用由 10 次降到 6 次，公共损失在 `1e-7` 绝对误差内一致，机制结果一致。一次 CPU 计时为 0.132 秒与 0.061 秒；这一小样本计时不用于推断整轮训练提速，CUDA 对照将在可用实验间隙完成。

CPU 消费者现在可以在 GPU 联合适配期间提前拟合，并写入部分完成清单。后续统一消费者流程复用其分类、回归模型，只补做时序卷积训练与最终评价；测试检查了提前拟合确实被复用、权重与串行版本一致、全部开发指标一致。提前计算使用一个独立 CPU 进程，线程数保持已验证的单线程设置，避免未测量的负载扩张。实际 CPU 工时保存在开发状态的 `cpu_prefit_results`，不因后续状态显示恢复而计为零成本。

候选压力评价支持独立 CPU 推理，读取当前候选内部验证选中的检查点及干净消费者，核对同一 512 条训练轨迹清单。CPU 推理仍须通过干净表示最大差不超过 `1e-6`、有效掩码一致和消费者预测重放检查；失败则记录为不可复用，不放宽误差阈值。该路径不进行神经网络训练。首次真实 CPU 重放的序列最大差为 `1.907e-6`，超过预设 `1e-6`，自动 CPU 压力队列已停止，未采用其结果；压力编码保留 GPU 路径。

## 实测负载与未采用方案

GPU 训练进程约占一个 CPU 核心，采样期间 RTX 4090 的计算利用率为 48%–81%，显存约 3.4 GiB，功率约 114 W。此前已完成单元中，随机卷积特征方法 MiniROCKET 的 CPU 拟合约 27–29 秒，因果时序卷积消费者的 GPU 训练仅约 0.4 秒。因此优先让 CPU 拟合与编码器适配重叠，而非仅把两种消费者同时启动。

相同 1,024 个训练窗口、256 个验证窗口的 CPU 回放中，进程内切换到八线程的两次方案均发生段错误，退出码 139，日志完整保留。随后采用独立进程、启动前固定线程数：单线程约 33.46 秒，八线程约 34.57 秒；分类预测与概率相同，回归预测最大差约 `1.38e-5`。这一测量未显示收益，故未采用八线程方案，不据此改变科学协议或更新运行中的模型。

## 测试与运行边界

聚焦正确性与并发检查为 11 项通过，完整 CPU 回归为 **550 项通过、29 项跳过**。测试期间 GPU 冻结训练持续运行；CUDA 检查未通过并行测试隐式争抢显卡。CPU 推理接口增加后另跑相关集成测试，记录见本目录 `validation_summary.json`。

当前候选训练使用冻结提交 `ed2e24e3`，其源码和已完成检查点保留。参考模型已完成 300 次预训练并进入 50 次头预热、200 次联合适配；后续压力与性能修订使用独立输出目录。正式公开确认、三种子选型和消融仍属于完整计划的待完成内容，工程通过不替代这些结果。

## 提前准备正式公开数据

公开原生窗口准备复用同一实现，新增明确的确认池角色；开发与确认缓存不能互相覆盖，加载时核验实际受试者集合及目标来源。CogPilot 28 人和 CLARE 15 人的确认池只进行数据准备，不输出模型成绩或拟合归一化。两个 CPU 进程可与 GPU 候选训练并行。原开发缓存的 2,524/794 个窗口仍可原样加载，角色与覆盖检查四项通过。仿真确认轨迹仍在模型冻结后生成。
