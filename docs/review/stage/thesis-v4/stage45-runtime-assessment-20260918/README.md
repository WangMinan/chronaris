## 建议的有界方案

先准备隔离验证，再决定暂停迁移。建议为首轮性能判断预留 4–8 小时的工作预算；这是建议的投入上限，不是对开发或验证耗时的保证。当前生产运行继续推进，单卡性能对照在安全检查点之后安排独占窗口，避免竞争改变计时。

1. 用相同检查点和输入，分开测量完整预训练更新、完整验证和联合微调；同步记录功耗、频率、CPU 墙钟及 GPU 时间。复用已有 `run_checkpoint_performance.py` 和性能对照工具；联合微调需按实际机制、非机制路径补充适用验证。
2. 先确认 P8 低频的影响，再针对普通执行递推验证现有图实现；禁止仅修改资格 JSON。若图执行仍超差，考虑仅迁移通过原判据的验证或导出路径，分别记录资格，不强行扩大到整个训练流程。
3. 保持输入顺序、微批量 4、有效批量 16、单精度、目标、更新预算和选模规则。验收包含前向、损失、梯度、参数、优化器与随机状态对照，以及独立进程恢复逐值一致；有语义和时移机制时必须覆盖实际非零权重阶段。
4. 以剩余受影响墙钟乘以节省比例计算收益，超过验证与迁移成本并留出余量才采用。例如剩余受影响工作为 60 小时、端到端加速为 2 倍、成本为 8 小时，净节省约 22 小时；若只加速占总耗时 20% 的部分，即使该部分快 5 倍，整体也只有约 1.19 倍。
5. 未通过原容差或收益不足时，继续原流程完成固定矩阵。增加 CPU 线程、并发训练、扩大批量、混合精度、新编译框架均不作为本轮首选。

研究候选目前仍有保留价值。CLARE 的四种配置已因分类宏平均 F1 退化超过 0.01 失去最终入选资格；单流保真配置的自监督 F1 为 0.4578、回归均方根误差为 3.1116，任务引导为 0.4834、3.1907。相对参考，两条回归分别改善约 7.1% 和 14.2%，分类未退化；它仍需 CogPilot 结果才能最终判断。依据当前固定规则，后续最多一名候选，若入围会执行 16 个公开复核单元及一个鼎新单元；零入围则汇总结束。此判断不授权跳过其他已冻结单元。
