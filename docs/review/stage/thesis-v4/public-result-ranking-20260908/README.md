# 公开复核结果校验与数据域等权排名

公开首折结果读取器已复用原生消费者重放校验，并接通按任务、数据域和训练种子汇总的排名函数。当前真实入口返回等待公开复核计划、零个排名；候选采用和最终配置仍需完成既定三种子复核。

读取器核验选型计划及公开受试者清单，重新读取仿真初筛与压力证据，再核对公开候选的源码、架构、数据角色、300 次预训练和 50+200 次任务引导更新。表示必须来自所选检查点，并包含完整训练与验证窗口；消费者模型、预测和指标通过重放后才能进入排名。

每个公开任务先汇总固定验证受试者，使用相同线性消费者主指标。排名先在任务内比较候选，再对仿真、CogPilot（虚拟飞行公开数据）、CLARE（认知负荷公开数据）等权汇总；仿真的三个任务不会比每个公开域的两个任务获得更多数据域权重。三种子路径对每个种子形成名次，再取名次中位数，同分优先各域模型参数量之和较少、其次实际训练耗时之和较少的配置。

尚未完成的单元使完整排名保持等待；已记录失败的候选不借用另一个数据域的成绩填补。修复参考缺失时对应方法和路线不能得到有效排名。鼎新没有加入该公开选型矩阵，其当前外层内容隔离问题按独立审计保留。

合成集成测试实际拟合消费者、保存和读取表示、重放预测并核验阶段数据。首次测试暴露了时间戳指纹格式不一致：文件采用 64 位时间戳，内存允许 32 位。来源指纹现按导出格式精确提升时间戳类型，数值不变；新用例可在重载后复核相同表示，并在检查点文件变动时拒绝读取。

## 执行失败状态修复

汇总器现在区分尚未完成与已执行失败。原压力队列已经保存失败单元，但读取器只检查完整结果，导致失败候选永远显示为等待；修复后按方法、候选和表示路线读取队列失败，返回明确的阻断状态并保存队列路径与哈希。整个压力队列在 CUDA（显卡计算）验证或编排阶段失败时也会显式阻断。

公开首折计划同步传递该状态；公开结果读取器删除了把任意执行失败直接排除后继续排名的逻辑。执行错误尚未区分来源不符、重放失败、硬件问题与模型正确性失败，不能据此做研究淘汰。成功记录继续保留；修复执行原因或验证候选失败归因后继续。参考失败不会换用其他候选充当参考。

针对性检查 13 项通过，覆盖干净与压力阶段的参考及非参考失败、路线独立性、队列整体失败和公开入口停止选型。实际首折预检查仍为等待仿真与压力完成，零个选型单元。运行中的冻结工作树保持原样；后续入口使用当前修复后的读取器重新核验证据。

修复后的完整 CPU 回归为 585 项通过、30 项跳过，用时 133.64 秒，日志哈希与实际预检查状态已追加至同一验证摘要。
