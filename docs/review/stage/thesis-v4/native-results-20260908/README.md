## 保存与恢复

消费者拟合和归档校验复用同一数据、目标、表示指纹计算。新消费者清单同时记录模型与结果文件哈希，恢复前检查已存在的全部文件，避免重新计算后覆盖发生变化的结果。归档校验加载保存的表示、模型和原始目标，重算全部预测及分组指标，不重新拟合编码器或消费者。

旧格式缺少独立文件哈希时，仍检查输入协议、模型来源并进行数值重放。首次部分归档的 23 个单元通过；后续独立进程复核发现鼎新第一折的参数上下文不一致，旧部分归档和失败日志均保留，未放宽哈希或数值判据。

## 鼎新问题与修复

机动分数原先沿输入统计表的字段顺序求平均，而字段最初来自无序集合。不同进程的字段排列导致双精度累加末位不同；本次第一折观察到尺度和持久性值约 `1e-16` 的差异，保存的目标张量和表示哈希仍一致。

共享机动分数函数现按语义字段固定顺序计算。语义行置换测试要求精确相等，真实两折目标又分别在 Python 哈希种子 17、29、43 的独立进程中构造，两折的参数上下文及目标哈希均一致。这些哈希种子用于检查运行时集合顺序，不是新增模型训练种子。

公开数据的 18 个基线单元继续保留原冻结来源；鼎新六个单元使用修复后的独立输出目录，不增加候选比较机会。旧检查点、模型、成绩和失败证据保持原样，完成重跑后再生成完整归档。

[验证摘要](validation_summary.json)记录 575 项完整 CPU 测试通过、30 项跳过，以及真实跨进程检查。共享读取入口位于 `v4_native_result_audit.py`；`fixed-native-results` 阶段支持显式 `--dingxin-results-root` 指定重跑来源，来源目录和哈希逐单元记录。
