## 失败定位与修复范围

失败已定位到两条导出路径的池化设备差异。报错为 `clean fitted consumer predictions changed: validation_linear_regression`，固定验收要求绝对差不超过 `1e-6`、相对容差为零。对留存文件的复算结果如下，支撑“序列相同、池化和线性预测出现末位差异”的判断。

| 检查对象 | 最大绝对差或结果 |
| --- | ---: |
| 256 个窗口的序列表示 | 0 |
| 时间戳、有效掩码、样本身份、任务真值 | 一致 |
| 池化表示 | 4.76837158203125e-7 |
| 线性回归预测 | 1.0728836059570312e-6，仅 1/256 个超过阈值 |
| 其余已存分类、时序分段与时序卷积特征回归预测 | 一致 |
| 从相同序列重新进行 CPU 池化 | 精确复现干净导出池化 |
| 从相同序列重新进行 CUDA 池化 | 精确复现压力导出池化 |
| 原干净池化送入同一已拟合线性消费者 | 精确复现原干净预测 |

`application_finetuning_export.py` 的任务引导导出先将序列复制到中央处理器（CPU），再进行池化；压力路径使用 `common_pretraining.py` 的 `TrainedFusionAdapter`，在图形处理器（GPU）上池化后复制。上述干预复算支持这处归约差异是本次预测检查失败的直接原因。压力来源散列额外包含条件标记，由 `v4_development_conditions.py` 构造，不能要求其字符串与干净训练来源散列相等。

后续修复应统一训练导出、压力导出和正式导出的池化规则，在共享调用路径处理，并对本次真实失败窗口验证；保持原阈值，保留旧文件和失败记录。还应补齐压力子队列异常终态。仅添加 `--retry-failed` 会使用原实现，不是已验证修法。本轮按盘点范围完成诊断，没有执行修复或重新训练。

近期方法存在官方实现，值得先做有截止点的适配检查；本轮未下载权重或启动适配训练。下列定位已于本次检索官方来源复核，实际选择仍应由任务匹配、可运行性和预算决定。

- [SensorLLM 官方实现](https://github.com/cruiseresearchgroup/SensorLLM)：2025 年自然语言处理会议 EMNLP 的传感器—语言对齐与活动识别方法，可作为分类适配候选；航空或生理负荷迁移需说明适配差异。

建议先冻结一个真正使用语言预训练模型的方案和一个时序基础模型方案；不要求三者全部展开完整矩阵。表示比较保留统一消费者；原生任务比较统一历史截止时点、目标、角色和指标，保留方法合理的原生输出方式。成本至少记录总参数、可训练参数、适配时间、峰值显存、单窗口延迟和批量吞吐；带缓存的方案分别报告首次成本与复用成本。
