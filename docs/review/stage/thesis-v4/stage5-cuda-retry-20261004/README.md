## 复核顺序

1. 保存原控制器状态、第 168 个单元的失败记录、日志和失败尝试成本。
2. 将训练报错与宿主机显卡事件按时间对齐，检查首次异常与后续清理异常。
3. 核验冻结源码、输入、完成收据、模型及下游文件；执行现有图计算和队列恢复测试。
4. 验收通过后使用原入口的 `--retry-failed` 显式重试，保留失败历史；确认更新越过原失败位置并实际保存检查点。

## 已有证据

Windows 宿主机于 2026 年 10 月 3 日 16:00:45.967 和 16:00:45.972 记录 NVIDIA 驱动事件 13 与 153，分别包含 `Graphics FECS Exception: Logging error 0x2` 与 `Error occurred on GPUID: c200`。训练进度于 16:00:46 写入显卡启动失败，控制器于 16:00:50 退出。首次调用栈位于负样本前向的观测整理，随机状态恢复异常发生在清理阶段。

时间相关性支持先做同源码显式重试，尚不能单独证明驱动、硬件或算法中的最终触发源。当前不据此修改计算实现，也不屏蔽错误或降低研究判据。

现有 CUDA（统一计算设备架构）图输出、梯度、累积与恢复，以及队列失败保留测试共 11 项通过。测试也出现同类梯度流警告但正常完成，因此警告本身不足以证明它是此次退出的原因。最终恢复现场及凭证见[恢复报告](../../../../artifacts/runs/2026-10-04_v4-stage5-cuda-retry/report.md)。
