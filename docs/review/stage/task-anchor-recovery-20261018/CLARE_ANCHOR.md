# CLARE 评分时间锚点核查

**目前可以确认评分协议和文件来源，尚不能确认每条记录的评分行到绝对信号时间的唯一映射。** 本轮没有发现足以直接修正为“所有文件平移 120 秒”的证据；现有映射保持原样。

## 来源链与已确认事实

**原论文说明了评分触发方式，但没有发布逐次报告时间。** [论文第三节](https://arxiv.org/html/2404.17098v2#S3)描述每段实验 9 分钟，以 10 秒蜂鸣提示触发口头评分，信号由 iMotions 同步采集；另有实验前休息基线与会话间休息。[第四节](https://arxiv.org/html/2404.17098v2#S4)采用 10 秒信号分段。将每行评分与相邻 10 秒段关联符合这一实验组织，但原文没有把口头评分定义为该段连续负荷的精确平均，也没有给出公开文件的逐记录裁剪原点。

**本地说明对应当前正式发布，缺口不是仅靠换一个 README 就能补齐。** 作者当前[代码仓库](https://github.com/Prithila05/CLARE)指向 [Borealis 数据集](https://doi.org/10.5683/SP3/H0AELT)。本轮读取其公开 API，发布版本为 1，发布日期 2025-10-24；六个发布文件为五种压缩数据包和 README。文件名及大小与本地接收清单一致，README 的 MD5 完全一致。没有重新下载全部压缩包或验证其全量压缩包散列，不能据此宣称所有解压文件与远端逐字节相同。

当前作者仓库只有说明、许可和传感器示意图，未提供评分配准或导出脚本；公开问题列表返回空。原始数据根目录除 CSV 外只有 README 与接收清单。检查了四名开发受试者的各模态文件头、脑电及外周时间范围和基线文件；评分 CSV 没有时间列，眼动文件中的注视／扫视片段字段也不是蜂鸣或评分标记。来源查询见 [online_source_queries.json](online_source_queries.json) 和 [source_inventory.json](source_inventory.json)。

## 0／120 秒起点的解释边界

**文件中存在两种时间原点约定，基线文件支持“裁剪／重置方式不同”的可能性。** 下表概括四名开发受试者，逐记录完整表见 [clare_anchor_evidence.csv](clare_anchor_evidence.csv)。

| 受试者 | 实验脑电起点 | 基线文件观察 | 可以作出的判断 |
| --- | --- | --- | --- |
| 1390 | 约 120.004 秒 | 四个基线均约 0—121 秒；实验段约 538—539 秒 | 实验段起点与基线尾部相邻，并非直接证明信号或标签延迟两分钟 |
| 1624 | 约 0.004 秒 | 只有初始基线，约 182 秒 | 实验文件看起来重置了时间原点；未公开重置规则 |
| 1629 | 约 0.004 秒 | 初始约 181 秒，其他基线约 109—122 秒 | 基线和实验文件各自从零附近开始，不可简单按文件时间拼成连续时钟 |
| 1674 | 约 120.004—120.008 秒 | 三个约 121 秒基线，另有约 183 秒基线 | 与保留休息段偏移的组织相容；首实验只有 42 个有限评分，第四实验缺失 |

第 1674 名受试者首实验的标签表有 54 行，其中 12 行为空，因而当前冻结清单保留 42 窗；这不是“54 个有效评分被无故裁成 42 个”。15 个开发记录合计 794 窗，原始评分复算已通过。两流首个有效采样的差异不等于设备时钟误差，可能包含设备启动或缺失；不把各流分别减去首样本时间作为“修复”。

## 当前代码假设与可修复入口

**当前加载器用脑电首时间作为评分行零的区间起点。** `src/chronaris/dataset/clare_native.py` 将行号 j 映射到 `[eeg_first + 10j, eeg_first + 10(j+1))`，三类信号共同使用这一窗口；它没有读取任务开始或蜂鸣标记。原始值复算只证明实现符合该假设，不独立证明假设真实。

若获得原始标记，建议新增独立锚点清单，而不覆盖旧加载规则：`subject_id`、`experiment_id`、原时间单位、各流时钟来源、任务开始时间、首蜂鸣时间、评分行号、实际报告时间、报告关联区间、裁剪与重置规则、来源文件及散列。映射只能由这些来源确定，不根据哪种平移使模型成绩最好确定。

可直接处理的是清单身份、缺失标记、标签等号阈值、端点和来源声明；这些不需要训练。已确认的逐记录时间修正需要另建任务版本并重新导出兼容表示，旧检查点和旧结果保持冻结。仅修改训练标签而复用不同时间窗的缓存会造成新身份错误。

## 决策

**CLARE 暂时保留为明确映射假设下的协议内结果，不升级为已经核实精确时间锚点的主要证据。** 本轮进一步收窄了缺口：需要任务开始／蜂鸣／口头报告日志，或作者的数据导出与评分配准说明；单纯数值检查无法恢复这些信息。本轮没有发送作者询问。

如后续能够取得依据，可修复映射并开展标准任务评价。如无法取得，按发布文件起点与评分行序组织的 10 秒负荷分类仍可作为明确假设下的基准候选，并完整披露该映射；缺少逐次蜂鸣日志不等于所有负荷分类均无效。若论文要求精确评分时刻、真实跨流延迟或时间因果结论，则该类主证据应转到提供明确标记的数据。会话级探索同样需确认文件与会话身份，样本量会减少，不直接视为替代主实验的达标办法。不以当前低分断言整个公开数据集失效。
