# 功能、数值与性能验收

**完整方法和实测应用均通过真实GPU服务链路。** 参数、所有输入张量和前向输出逐批记录为cuda:0；输出返回CPU进行标准封装，服务没有静默回退。63项定向代码测试通过，涵盖新增设备隔离、不可用GPU、内存不足错误保留和标准适配器等价性。

下表给出本轮功能与数值检查的条件和实际结果。两类案例分别保存来源，统一沿用绝对与相对容差各10⁻⁵。

| 检查 | 条件与预期 | 实际结果／证据 |
| --- | --- | --- |
| 模型和输入在GPU | 模型参数、全部输入张量、前向输出须位于同一GPU | 全部记录为cuda:0，numeric-comparison.json |
| 完整方法CPU/GPU | 同权重、同输入、固定归一化 | 序列最大差1.43051×10⁻⁶，汇总2.38419×10⁻⁷ |
| 实测CPU/GPU | 原实测语义权重及相同三窗口 | 序列最大差1.07288×10⁻⁶，汇总2.38419×10⁻⁷ |
| GPU批量/逐窗口 | 批大小2与逐窗口 | 完整方法1.19209×10⁻⁶；实测9.53674×10⁻⁷ |
| 历史信息边界 | 扰动15秒之后的有效观测 | 两类案例的历史前缀最大差均为0 |
| 语义参与 | 完成权重的语义分支诊断 | 两类输出均发生变化，查询参数非零；各自mechanisms.json |
| 标准交付 | 时间、样本、有效性、序列和汇总一致 | 下载、CSV逐值、回读及有效时刻均值通过 |
| GPU中断恢复 | 16窗口任务完成片段后中断进程 | 重启复用1个完整片段，完成全部窗口，原失败记录保留 |
| 跨设备恢复 | GPU请求指向已有CPU片段 | 复用数0，三个窗口实际在GPU重新执行 |
| GPU互斥 | 已有GPU服务时启动第二服务 | 明确拒绝；结束后释放锁 |
| GPU不可用／显存不足 | 构造错误路径 | 明确失败、请求保留，无自动CPU回退 |
| 输入错误 | 真实观测的重复、冲突、字段、时间、掩码和非有限值 | 去重或按预期返回400，原输入保留 |
| 浏览器完整功能 | 模型选择、历史身份、时间/维度、下载、增量与短暂断连 | 20项通过，脚本异常0，见simulation-ui/browser-check.json |
| 实测GPU界面 | 同一GPU任务的四视图和实际汇总交付 | 通过，measured-ui/browser-case.json |
| 设备标识 | 服务、任务、历史结果分别保存 | 页面与结果设备可核对，CPU与GPU任务不会混标 |

**性能按同一完整仿真模型、同一输入顺序比较两种设备。** CPU为AMD Ryzen 9 9900X，GPU为RTX 4070 SUPER，驱动617.42，PyTorch 2.11.0＋CUDA 13.0；CPU线程1、批大小1、浮点32位，关闭TF32。每设备选1、4、16窗口各三次，共18次。每个设备使用独立的新服务进程，仅第一任务标记为首次任务；系统文件缓存未清空。每次重新加载检查点，不复用已完成片段。

| --- | --- | --- | --- | --- | --- |
| CPU | 1 | 4.8756 | 0.0221 | 4.9340 | 5.0589 |
| CPU | 4 | 4.7929 | 0.0804 | 4.9938 | 5.1303 |
| CPU | 16 | 4.7335 | 0.3140 | 5.5240 | 5.7210 |
| GPU | 1 | 5.2311 | 1.6698 | 6.9804 | 7.1100 |
| GPU | 4 | 4.8151 | 1.3087 | 6.2594 | 6.4155 |
| GPU | 16 | 4.9811 | 1.7042 | 7.2257 | 7.4907 |

完整训练检查点的读取、严格加载和GPU计算图准备计入当前流程，因此这组小任务中GPU更慢。此结果反映每任务重新加载的应用成本，不外推持续驻留模型或更大批量的吞吐。计算图每个新模型重新准备，其开销进入forward_s；后续重复只表示框架和文件缓存已预热。

GPU阶段在边界调用同步函数：normalized_s为CPU训练归一化，input_transfer_s为设备搬运，forward_s为实际前向及计算图准备，output_transfer_pool_s为返回CPU和有效时刻汇总。其他字段分别计输入读取、片段写出、标准包/CSV回读、JSON/压缩包以及完整管线。HTTP完成、结果查询和汇总交付从客户端提交计时，含50毫秒轮询等待。完整管线结束在压缩包写完，任务状态写入包含在HTTP观察时间内。

服务进程内存来自服务PID的VmRSS/VmHWM。16窗口组的服务峰值最大为CPU 963.29 MiB、GPU 2197.71 MiB。GPU组的最大峰值分配为343.17 MiB、最大峰值保留为518 MiB，来自服务进程的PyTorch CUDA分配器，按任务重置峰值；保留量包含已有缓存，和系统级显存占用分别解释。验证器内存未混入服务指标。

GPU服务持有现有实验互斥锁，测量期间没有另一实验获得该锁；主仓同时进行资产恢复和下载，本轮亦有少量CPU文档与字段核查工作，未隔离整机CPU及磁盘；Windows桌面等背景负载仍可能存在。环境快照在 environment.json，GPU逐批设备证据在结果文件。浏览器首次就绪5903.93毫秒、结果切换65.23毫秒，属于单次交互样本，包含目录加载及浏览器等待。

纯标准库运行 summarize_performance.py 可重算均值、样本标准差、范围与内存汇总。原CPU实测语义包继续保留，其模型和输入不同，不混入本表。
