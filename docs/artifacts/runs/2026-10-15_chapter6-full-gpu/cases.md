# 完整方法与实测应用案例

**两类案例分别验证完整方法的软件承接和真实观测的应用流程。** 二者均通过GPU服务处理、标准下载及下游读取，截图和显示数据分别绑定各自的真实任务，不互换权重或数据角色。

下表给出可直接用于6.4.3的案例条件。机器标识与原始数值保存在同名证据目录，正文采用表中的中文名称。

| 项目 | 原生仿真完整方法案例 | 实测应用案例 |
| --- | --- | --- |
| 选择依据 | 既有内部验证划分的前三个上下文，按原顺序选择，不读取任务成绩 | 保留既有内部验证的前三个窗口 |
| 数据角色 | 受控仿真观测；完整物理及语义方法落地验证 | 航空人机实测观测；真实流程和字段条件验证 |
| 输入 | 7个生理字段、12个飞机字段 | 12个生理字段、965个航电字段 |
| 时间范围 | 30—60、60—90、90—120秒；三个30秒上下文 | 90—120、95—125、100—130秒；相邻窗口重叠 |
| 模型角色 | 已完成1500次更新的自监督编码器，五种运动学关系、观测锚定、连续对齐和事件语义 | 上轮独立实测语义编码器，观测锚定与事件语义；运动学关系按字段核查保持空集合 |
| 实际运行 | cuda:0，固定归一化，严格加载 | cuda:0，原实测字段合同与固定归一化 |
| 标准输出 | 3×96×64；285个有效参考位置 | 3×96×64；288个有效参考位置 |
| 来源目录 | simulation-ui | measured-ui |

**完整方法案例从已受五种物理关系约束的权重生成融合特征。** 物理残差属于原训练目标，服务推理使用完成权重，不在处理任务中重新训练。训练证据及本轮诊断见 physics-training.json；三窗口的事件摘要、历史前缀扰动与语义参与见 simulation-validation-mechanisms.json。第一参考位置早于可用观测时输出零及无效标记，解释了285个有效位置。

**实测案例保留实际字段有效性与原始时间。** 生理字段有效率70%，航电约49.5%；原生观测点、原始文件散列及每窗时间另存 input-summary.json。字段复核读取已有解释并保留人工确认状态，已核实的角度单位与尚需确认的速度/高度标度分别记录。该案例不把缺少依据的物理配对补成假测量。

- measured-ui中的四张图片：同一实测GPU任务的数据、字段、结果与交付。

将最后目录改为 measured-ui/feature-example 可检查实测案例。读取器核对序列形状、零占位、布尔有效性、时间、样本身份、CSV逐值一致及有效时刻均值。汇总为每窗口64维，供下游任务读取；表示维度本身不直接命名为业务状态。

两个案例的redraw目录分别保存完整显示数据、UI源码、样式和纯渲染脚本。它们已复制到仓库外独立重绘，输出2倍像素密度PNG及六份可编辑SVG曲线，不加载模型、不重新计算指标、不联网。修改显示数据时另存版本并保留原始输入。实际应用截图和重绘图分别命名，论文侧可按版面选择展示片段。
