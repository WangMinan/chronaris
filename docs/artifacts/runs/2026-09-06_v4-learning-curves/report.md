# v4 完整开发学习曲线

完整开发学习曲线已接入共享预训练器、任务引导训练器和统一消费者。入口的短预算端到端测试通过：真实 CUDA（统一计算设备架构）训练与三个阶段快照导出后，两条路线各完成线性、MiniROCKET（时序卷积特征）和因果时序卷积消费者，确认样本未访问。快照与恢复聚焦检查六项通过，开发角色与消费者检查两项通过。

本阶段先运行新仿真的五种可训练方法，均使用种子 17、32 维隐藏状态、实际批量 4 和有效批量 32。自监督训练固定 500 次更新；任务引导在相同自监督初始化之后预热任务头 50 次、联合适配 500 次；关闭早停。两条路线均保留 50/200/500 的阶段状态，再从头拟合相同消费者。完整仿真输入含 1,024 个训练与 256 个开发窗口，512 个确认窗口只保留身份清单。

阶段快照仍标记为训练中状态，仅显式的开发诊断接口可以读取；普通完整检查点入口继续拒绝，任务引导快照禁止导出确认角色。消费者清单分别记录编码器是否使用监督标签，开发评价不会被写成确认评价。

[预算诊断规则](../../../requirements/thesis-v4-budget-diagnostic.json)在新学习曲线成绩产生前固定。仅根据仿真开发验证损失判断是否扩大训练集：五方法两路线中，任一曲线同时满足 200 到 500 更新相对改善至少 2%、400 到 500 至少 1% 时，触发唯一一次增加 32 个参数档案；所有方法与路线同步使用扩展后的清单。非有限值按正确性失败处理，不作为扩容依据。该规则不用于跨方法比较预训练损失绝对值。

当前入口覆盖干净输入的学习曲线与消费者；八种开发条件、注意力与梯度分析、长尾分解、公开与鼎新完整诊断仍属于本阶段后续工作，尚未形成完整训练诊断包。正式候选和确认仍未启动。

复现入口：`scripts/evaluation/application_tasks/run_thesis_v4.py diagnostic --domain simulation --method chronaris`。其他可训练方法使用相同入口与预算。运行源码单独固定在只读用途的工作树中，主开发分支后续改动不会影响正在执行的训练单元。
