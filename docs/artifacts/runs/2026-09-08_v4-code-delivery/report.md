## 运行方式

在包含本次提交的冻结工作树中，使用仓库的 `chronaris` 环境运行。以下命令会先完整验证 CUDA（统一计算设备架构），再执行开发选型、配置冻结、正式主表、压力、核心消融、独立时间机制和最终统计报告。

```bash
/home/wangminan/env/anaconda3/envs/chronaris/bin/python /home/wangminan/projects/chronaris-runtime-v4-code-complete-20260908/scripts/evaluation/application_tasks/run_v4_pipeline.py \
  --root /mnt/e/chronaris-v4-results/2026-09-08-v4-complete \
  --until confirmation
```

增加 `--plan-only` 仅打印固定阶段与来源清单，不创建实验目录、不训练。`--until development` 停在开发采用判断后，`--until freeze` 停在配置冻结后；不指定时默认停在冻结。后续使用同一目录及相同源码重新运行相同命令即可恢复，也可将终点从冻结推进到正式评价。

入口检查运行目录锁、源码、输入清单和完成收据；数据提供器继续核验原生文件和各折角色。图形处理器（GPU）训练保持串行，中央处理器（CPU）消费者提前拟合，正式阶段的固定投影基线与神经训练可以并行。每 30 秒更新控制状态，训练器另外保留真实优化器更新数与完整更新边界检查点。

运行状态位于根目录的 `pipeline_state.json`，逐阶段日志在 `logs/`，每次尝试的结果在 `stage_results/`。失败不会静默跳过；检查并处理同源码瞬时故障后，可使用 `--retry-failed`，历史失败仍保留。源码修复或数据变更必须使用新目录，不能凭权重文件继续旧训练状态。

## 自动选型与有界分支

新源码初筛包含 26 个配置：融合模型十个固定配置、四种可训练基线各四个配置。相较已完成的历史 18 个配置，增加的是每种基线的固定缺失增强与多时域预测机会；没有扩大融合模型的九项单因素搜索。新完整初筛预算为 14,300 次编码器及任务头更新，不含消费者训练；此数字是待执行预算。

公开首折按两条路线独立选型，共有初始化只训练一次；常规完整复核仍为每方法每路线最多两个配置，公开三折和种子 17、29、43 固定。公共目标进入融合模型公开比较时，同样进入四种基线的公开比较；首折按相同规则淘汰后，不强制进入三种子复核。

解析衰减单元仅在同一连续缺失条件、同一状态分支的第 99 百分位范数超过干净参照十倍、并在至少两个种子复现后，自动追加一次开发比较。其连续演化为逐通道正速率指数衰减，观测更新继续使用原有门控单元，查询不写回轨迹锚点。新增候选完整覆盖仿真及公开三折三种子，复用已完成的父复核结果，既不重训父候选，也不打开确认数据。若收益不足，保留原配置及不稳定诊断，不递归增加候选。有效状态非有限等执行失败仍立即停止并保留证据，需先定位故障，不将其自动归因为可淘汰候选。

正式阶段要求全部主模型与适用核心消融模型先冻结，再生成新仿真确认数据。干净消费者拟合一次，35 种压力场景及两种整模态缺失复用该消费者。公开五折及鼎新单记录时间块评价使用原有角色合同；鼎新仍为描述性评价，不恢复重复的两架次外推口径。
