# 性能测量条件与复算方法

**性能记录针对最终展示配置，按真实可用窗口规模重复测量。** 选取同一实测观测记录的前1、3、15个窗口，每种规模重新启动服务进程，连续执行三次；每次重新加载模型并生成新结果，关闭任务增量复用。训练结束后再测量，测试设备为中央处理器，计算线程固定为1，实际硬件与软件版本见 `environment.json`。

性能输入取自模型已允许的归档范围，包含训练及内部验证观测，按记录顺序选取前1、3、15个窗口；这里测量运行成本。应用案例另固定前三个内部验证窗口，二者使用同一最终模型，观测选择分别记录。

每种规模的首次运行表示新服务进程中的首个任务。系统文件缓存不清空，因此这不是操作系统磁盘缓存完全冷态的测量；后两次属于同进程重复运行。三次原始记录全部保留，汇总使用算术均值、样本标准差、最小值和最大值。

下表定义各计时字段，避免把管线耗时、接口等待和界面响应混成同一个指标。完整阶段和未单列的目录、指纹、预览组织开销一起组成总耗时。

| 字段 | 起止边界／单位 |
| --- | --- |
| `service_startup_s` | 启动进程至监听就绪，秒；与任务耗时分开 |
| `model_load_s` | 管线进入至模型校验、严格加载和适配器就绪，秒 |
| `input_read_s` | 各窗口散列核对和观测读取的累计时间，秒 |
| `inference_s` | 张量整理、固定归一化、模型前向及标准表示构造，秒 |
| `chunk_write_s` | 标准片段及其显示数据写入，秒 |
| `cache_read_s` | 恢复片段读取及复制，秒；本次性能任务不复用结果 |
| `standard_export_readback_csv_s` | 合并片段、标准包写出、回读检查和序列表写出，秒 |
| `result_json_zip_s` | 最终结果JSON与压缩包写出，秒 |
| `pipeline_total_s` | 管线进入至最终压缩包写完，秒；不含计时文件自身及任务完成状态写入 |
| `http_completed_s` | 客户端提交至轮询观察到完成，秒；包含50毫秒轮询间隔的等待 |
| `http_result_s` | 客户端提交至完整结果查询结束，秒 |
| `http_delivery_s` | 客户端提交至标准回读汇总接口返回，秒 |
| `windows_per_s` | 窗口数除以完整管线耗时 |
| `VmRSS_mib` | 当前服务进程的常驻内存，二进制兆字节 |
| `VmHWM_mib` | 当前服务进程生命周期内的常驻内存峰值，二进制兆字节 |

内存来自服务进程的 `/proc/<pid>/status`。同一规模的后续重复继承该进程此前任务的峰值，不能作为每个任务独占模型内存解释。数值验收器的峰值另记为验证进程内存，不参与服务性能表。浏览器就绪和结果切换时间保存在 `browser-check.json`，包含自动化操作及浏览器请求、解析和渲染等待，属于有界交互样本。
