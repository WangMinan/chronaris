# 阶段 1：导出一致性修复与已有计算保留

本阶段完成共享导出池化和初筛压力失败终态修复。真实失败的 256 个开发窗口已通过原绝对容差 `1e-6`，所有干净预测数组与原预测逐值一致；独立重放完成八种压力条件。现有 52 份所选开发检查点与 14,300 次编码器及任务头更新可保留，无需为此次修复重新训练编码器。

## 修复结果

**所有可训练方法的冻结导出统一使用中央处理器（CPU）执行有效时间点均值池化。** 自监督、任务引导、压力和正式导出复用 `pool_exported_sequence`；无效时间点先置零，全无观测窗口输出零向量，神经编码仍使用图形处理器（GPU）。训练前向、损失、优化器、目标与阈值保持原实现。源码差异和具体函数已列入[复用清单](reuse_inventory.json)。

**初筛压力异常现在留下完整终态和失败历史。** 子队列记录失败单元、堆栈、时间与单元尝试次数，并清空正在运行的单元；异常继续传到总控。没有显式 `--retry-failed` 时保持失败；显式重试保留成功单元和失败历史，重跑失败单元。工作进程的终止信号（SIGTERM）转为可记录的中断，复用现有失败处理。

## 哪些计算保留，哪些需要重建

**昂贵的编码器训练和序列导出均可保留，重建集中在自监督路线的汇总与线性拟合。** 核验覆盖全部 26 个配置、52 条路线、104 份训练及验证表示，并在检查前后复核 1,106 份原输入或证据文件散列；最终重放后的[保留核验](preservation_check.json)再次确认全部未变。下表区分原样复用与后续新目录中的重建工作；这里的“复用”以现有数据、角色、训练监督和任务合同不变为条件。

| 产物 | 核验结论 | 后续动作 |
| --- | --- | --- |
| 52 份所选开发检查点及归一化状态 | 现有加载器严格加载通过；模型训练实现未变 | 原样引用，保留旧源码、权重散列和开发角色 |
| 14,300 次编码器及任务头更新 | 原预算和收据可复核 | 不重新训练编码器或任务头 |
| 104 份序列表示、时间、掩码及身份 | 应用新导出掩码规则后序列仍逐值一致 | 复用已有序列，无需重新执行神经编码 |
| 任务引导路线的 52 份完整表示 | 汇总向量也逐值一致 | 原样复用并登记来源 |
| 自监督路线的 52 份完整表示 | 原 GPU 与统一 CPU 归约产生末位差异 | 从已存序列重新汇总，在新目录生成完整表示和清单 |

**不应把汇总向量的末位变化当作无需处理的误差。** 自监督路线的汇总最大变化为 `9.5367431640625e-7`；把新汇总直接送入旧线性模型时，全部配置累计 25 个验证预测超过 `1e-6`。因此清单将这 26 组线性模型标为重新拟合，即使它们的时序模型和编码器可以保留。每配置、路线和角色的数值差异均在[机器清单](reuse_inventory.json)中。

**复用清单没有放宽旧队列的源码保护。** 工作流源码指纹仍覆盖训练、数据与评价，旧运行仍禁止直接用修复源码续跑；本轮没有修改其配置、收据或失败状态。后续在独立目录引用旧检查点、数据和序列，登记旧来源与新池化、新下游收据。近期方法引入后若改变任务、角色或监督合同，需要重新核定兼容性，不能凭本清单跳过新合同检查。
