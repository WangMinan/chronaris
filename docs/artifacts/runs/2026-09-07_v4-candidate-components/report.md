# 固定候选的注意力、同刻目标与独立配对实现

两种注意力方案、关闭同刻拉近及独立窗口配对已接入共享训练器和检查点加载。当前完成的是实现与恢复验证，尚未形成候选收益或冻结选型结论；后续候选实验统一使用已经激活的 512 条训练轨迹。

## 单因素接口

下表列出本批已接入的配置，所有其他设置继续使用修复参考。原共享事件库配对损失保持关闭；独立配对的起始权重固定为 0.1，后续不按确认成绩调整。

| 候选 | 配置 | 实际变化 |
| --- | --- | --- |
| 余弦注意力修订 | `attention_kind="cosine_temperature"` | 去掉额外的维度平方根缩放，温度初值 1，有界于 0.05–2 |
| 投影注意力 | `attention_kind="projected_dot_product"` | 单头独立查询、键、值投影，采用标准缩放点积 |
| 关闭同刻拉近 | `continuous_alignment_weight=0` | 只关闭同刻连续对齐目标，观测锚定、物理残差与因果方向目标保留 |
| 独立窗口配对 | `independent_pairing_enabled=True, independent_pair_weight=0.1` | 两模态分别按原生历史时间分四段池化，独立投影至 32 维后配对 |

独立配对向量从两模态各自的连续主干观测状态生成，不读取融合后的事件库。同一窗口为正例，实际前向批次中其他有效分组作为负例；同组其他窗口不充当负例，两模态都有效才构成配对样本。温度固定为 0.1，采用双向对比损失。无有效跨组负例明确记为不可用，梯度累积不增加负例集合。

独立配对遵守前 50 次更新关闭、50–200 次线性升权的机制日程。任务引导微调从自监督检查点恢复对应目标配置和配对投影；训练任务头移除后，主表示仍为 64 维，配对向量仅位于辅助输出。该目标是窗口级配对，不单独证明精确事件时延恢复。

参考配置不新增注意力或配对参数，旧版本推理的默认构造仍使用原注意力形式。按实际仿真字段构造的编码器参数量见[参数清单](parameter_counts.json)：参考 31,127；余弦温度修订 31,128；投影注意力 34,295；独立配对 39,383；既有 64 维容量接口为 111,319。参数量不包含公共预训练任务头。

共享训练器配置已移至 `candidate_config.py`，原导入入口继续可用；训练主文件保持低于 800 行。没有新增训练框架。

## 验证覆盖

注意力计算与手工公式对照、有效掩码、全窗无观测、历史扰动和温度边界检查通过。启用事件语义融合时，两种新注意力仍通过历史查询隔离检查。CPU（中央处理器）与 CUDA（统一计算设备架构）中途恢复覆盖模型、优化器、随机状态、增强记录和数据游标。

独立配对的原生时间分段、未来点排除、全空窗口投影偏置清零、双端置换独立性、完整实际批次负例及无负例状态均已验证。跨越第 50 次更新边界的连续与中断恢复，在 CPU 和 CUDA 上均产生相同训练状态；新增配对参数只在目标启用后出现相应训练梯度。

## 捕获失败与修复验证

首次完整测试保留了 **549 通过、4 失败、8 跳过** 的记录。最先出现 CUDA 图捕获失效，后续随机数和 dropout（随机失活）操作发生偏移状态错误。上游也记录了捕获失败可能破坏后续随机数状态的现象，见 [PyTorch 问题记录](https://github.com/pytorch/pytorch/issues/171263)；该记录解释了后续错误，不能单独证明本地最初失效的原因。

本地代码检查发现图与模块的循环引用可能延迟到后续捕获期间回收。当前修复在捕获前收集旧对象，捕获期间暂停自动垃圾回收，并在成功或异常退出后恢复调用前设置。新增检查直接确认真实捕获期间的回收状态与异常后的恢复；包含多个注意力模型、独立配对、连续重放与中断恢复的同进程复核 **13 项通过**。没有改变连续单元方程、精度、批量或优化器日程，也不在捕获失败后静默切换执行方式。

修复后的完整 CUDA 环境测试为 **554 项通过、8 项跳过**，用时 212.87 秒。随后独立配对的任务引导检查也通过：对应投影参数继续更新，移除训练任务头后正常导出 64 维训练与验证表示。具体日志和失败记录见[验证摘要](validation_summary.json)。单流保真、质量门、扩大缺失覆盖及多时域预测仍待接入；九候选的正式初筛、三种子复核与最终配置冻结尚未开始。
