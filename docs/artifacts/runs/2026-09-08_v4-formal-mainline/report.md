# 仿真与原生正式训练接续

正式主表的执行入口已接通仿真、公开数据及去重后的鼎新。共享训练器负责预训练和联合适配；共享队列负责独立进程、显卡互斥、心跳和恢复。已完成单元的回执发生变化时拒绝复用，源码和测试完全相同时复用已经通过的 CUDA（统一计算设备架构）验证收据。

仿真先完成冻结配置下的六方法、三种子、两种表示路线，固定网格投影在 CPU 拟合；所有选定模型检查点及训练数据清单核验后，才冻结模型文件并生成 G2（事件样条生成族）确认数据。确认集为 16 个参数档案、128 条轨迹、每条四个上下文。原有 35 种锁定压力场景另加一份干净异步输入，生成清单共 36 种观测；两种整模态缺失按掩码移除该流的观测点，保留另一路原生观测。

干净消费者拟合后用于全部压力场景，保持统一分类、回归与机动分段指标。每条路线保留一次干净重放核验和 37 种压力条件；长尾、无观测覆盖与参数档案指标复用原有统计函数。固定网格基线两条路线共享同一份投影与消费者，避免重复拟合。

自动链先并行执行仿真神经训练、仿真固定投影和原生 CPU 基线；仿真确认生成后，仿真评价与原生神经训练共用同一显卡锁。队列状态、单元日志和回执明确记录等待、完成及失败。此链覆盖主表与仿真压力，核心消融、跨域汇总和论文材料仍在后续范围内。

[完整 CPU 验证](validation_summary.json)为 611 项通过、30 项跳过，耗时 150.46 秒；随后仅增加同源码 CUDA 收据复用检查，三项聚焦验证通过。工程测试实际运行短预训练、联合适配、固定投影、统一消费者及全部压力分支；另用独立工程命名空间生成一条 G2 轨迹，验证原生读取、完整上下文及两种整模态掩码，未生成正式确认轨迹。

运行入口为 `scripts/evaluation/application_tasks/run_thesis_v4.py` 的 `simulation-confirmation-train-cohort`、`simulation-model-freeze`、`simulation-confirmation-data`、`simulation-confirmation-evaluate-cohort` 和 `native-confirmation-cohort`。正式训练均要求冻结配置哈希，确认数据生成和仿真评价还要求冻结模型清单哈希。`run_v4_confirmation_chain.py` 只负责顺序与 CPU/GPU 并行调度，不重新实现训练和评价。
