## 性能结果与执行选择

CUDA Graph（显卡运算图重放）是本轮有明确收益的执行改动。下表对比同一第 200 次检查点出发、相同样本和相同损失下的两个完整更新；每次实际批量为 4，四个微批次累积后完成一次参数更新。核心计算计时包含微批次加载、归一化、增强、前向、反向与优化器步进，不含输入全量核验、梯度快照、裁剪和诊断文件写入；试验总耗时包含这些准备与诊断工作，不能直接当作完整队列成本。

| 执行方式 | 第一个更新核心计算 / 秒 | 第二个更新核心计算 / 秒 | 两次核心计算合计 / 秒 | 试验总耗时 / 秒 |
| --- | ---: | ---: | ---: | ---: |
| 普通执行，1 个中央处理器线程 | 127.81 | 313.71 | 441.53 | 617.65 |
| 显卡运算图重放，1 个中央处理器线程 | 15.09 | 23.45 | 38.54 | 208.69 |
| 显卡运算图重放，8 个中央处理器线程 | 14.89 | 23.18 | 38.07 | 193.49 |

加速版本首个更新包含运算图首次捕获成本；第二个更新复用运算图。相对于普通执行，核心计算合计加速 11.46 倍，包含准备与诊断的试验总耗时缩短约 2.96 倍。PyTorch 深度学习框架记录的峰值显存分配从约 1134.26 MiB 降至 788.54 MiB；这不是显卡管理接口的总驻留显存读数。

增加至八个中央处理器线程仅让核心计算时间再缩短 1.23%，两次运行的结果逐值一致。本轮没有重复交错试验，不能将这一小幅差异认定为稳定收益。因此推荐保留一个中央处理器算子线程，优先接入已验证的显卡运算图重放；下一步是显式迁移执行版本和第 200 次检查点后恢复队列，不追加大批量、混合精度或新的并行框架。

检查使用 PyTorch 2.11.0+cu130、RTX 4090 显卡、确定性算法和原有单精度设置。显卡测试及首次捕获出现过自动求导节点的流同步警告，原[测试日志](cuda_tests.log)和运行日志保留，未通过关闭警告改变检查结果。该试验验证固定两次更新及一次独立恢复，不代表后续全部更新与普通实现始终逐值一致；正式恢复必须记录执行版本变更，不直接把诊断文件当作生产检查点。

显卡资源记录只作辅助证据，收益按相同更新的单调时钟计时判断。[NVIDIA 的 WSL 官方说明](https://docs.nvidia.com/cuda/wsl-user-guide/index.html#features-not-yet-supported)指出，部分显卡管理查询存在功能限制。本轮停止后确认空闲，并在试验期间持续记录资源与计算进程。
